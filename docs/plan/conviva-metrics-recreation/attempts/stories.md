# Attempts — story specs

> One task per session. Find the first unchecked item in `tasks.md`. That is your only task. After each task: set `SHA:` on the task line + tick the box, update the epic `README.md` status, add one
> line to the backlog/session-log file.

**Build rule (user, 2026-10-27):** scratch and POC scripts only validate feasibility. Formal scripts and helpers are built and tested while working these tasks (CMR-ATT-4 to CMR-ATT-9), never through
MCP and never deferred to the end. Read the existing runners and helpers first and reuse or enhance them (`run_athena_debug_sessions.py`, `lib/runtime.py`, `flatten_debug_events.py`); shared logic
such as `day_bounds()` lives in one shared helper, also used by the `concurrent-plays/` story (CMR-CP-2). The report writer's top-content and breakdown helpers are shared with the concurrent-plays
report.

**Final report format (user, 2026-10-27):** short, tables and the chart with a 1-2 line summary each. Sections: definition (few lines), headline with the chart, top-10 content, device breakdown,
playback type. No sensitivity, "Reconciliation", "Known gaps" or local file paths (only the chart image link); assumptions live in the story. Apply this when the report is next regenerated: drop the
"Generated by `scratch/...`" line and the `session.csv` file name, and add the device and playback-type tables (CMR-ATT-9).

Tests: scratch scripts are exempt from the test gate until graduation (CMR-ATT-7); verify by running on local data and recording the output. Confirm scope and plan with the user before creating or
editing anything (project Steps 2-3).

**What the POC reads (derive the formal inputs from this):**

| POC input | Used for | Formal source |
|---|---|---|
| `<date>_debug_states.csv`, CREATE rows | attempt = distinct `sessionId`, CREATE time for the bucket | CREATE events in the CMR-CP-2 raw export, or the `ctap-smvod-debug-states` query |

**Files:** catalogued query or queries under `queries/athena/`; a runner in `investigations/ctap-smvod/scripts/` modelled on `run_athena_debug_sessions.py` (`--date/--tenant/--dry-run/--force`,
`day_bounds()` from the shared helper) unless the CMR-CP-2 export already covers it; a loader helper in the shared lib; the registry and `docs/usage.md`.

2. Prefer one raw export for the whole day over several parsed ones: check that the CREATE `eventdata` (title, content type) reproduces the POC's attempts count and titles for ZA, 2026-10-24, and

3. If household is not in `eventdata`, add a catalogued query for it. Record any field that only a local file provides as a task, not a guess.
4. Fetch for any tenant and date, never hardcoded, and save the export where the report reads it.
