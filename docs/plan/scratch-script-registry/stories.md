## SSR-1 — `scripts/dev/generate_scripts_registry.py`: scan + write root `SCRIPTS.md`

**Files to change / create:**
- `scripts/dev/generate_scripts_registry.py` — the generator
- root `SCRIPTS.md` — left untouched by this task (SSR-7 runs it for real); this task only needs the script to be correct and manually verifiable against a scratch fixture tree

**What to implement:**

1. `find_scripts(root, subdir)` — find every `*.py` / `*.sh` file directly under `scripts/` (recursively, including `scripts/dev/`) or `scratch/` (recursively, including `scratch/_lib/`), skipping
   `__pycache__`/`.venv`/`node_modules`/`.git`. Return sorted paths relative to `root`.
2. `extract_purpose(path)` — for `.py`: first non-empty line of the module docstring. For `.sh`: first `# ` comment line after the shebang. Return `None` if neither is found (do not raise).
3. `extract_scratch_date(path)` — parse the leading `YYYY-MM-DD` from a `scratch/`-relative filename per `SCRATCH.md`'s naming convention; return `None` if the filename does not match (e.g. a
   `scratch/_lib/` helper, which is exempt from the date-prefix convention).
4. `build_registry(root)` — returns the full `SCRIPTS.md` markdown text: a "## Scripts" section (table: Script | Purpose) from `scripts/`, then a "## Scratch (unpromoted — check here before writing a
   new one)" section (table: Script | Date | Purpose) from `scratch/`, sorted by path within each section. A short header explains it is auto-generated by this file — do not hand-edit.
5. `main()` — `argparse` with `--root` (default: repo root, resolved from this file's location) and `--out` (default: `SCRIPTS.md` under `--root`). Writes the file, prints the output path.

**Tests:** written in SSR-4, not here (matches this story's own task split, mirroring the `tenant-registry` story's precedent of separating implementation from its test-completeness task).

**Commit:** `feat(scratch-registry): add generate_scripts_registry.py`

## SSR-2 — `scripts/dev/promote_scratch_scripts.py`: manual promotion CLI

**Files to change / create:**
- `scripts/dev/promote_scratch_scripts.py`

**What to implement:**

1. `find_promotion_candidates(scratch_dir, min_age_days)` — reuse SSR-1's `extract_scratch_date` (import from `generate_scripts_registry`, do not re-derive the date-parsing logic — this is exactly the
   "same fetch/parse boilerplate" case `SCRATCH.md`'s convergence rule warns about, except here it is production `scripts/dev/` code sharing with sibling production code, which is plain reuse, not a
   scratch `_lib/` extraction). Return scratch scripts whose date is at least `min_age_days` old, sorted oldest first. Files with no parseable date are excluded (nothing to age-compare).
2. `promote(script_path, dest_dir)` — validates `script_path` exists and is under `scratch/` (raise `ValueError` otherwise — this CLI must never be pointed at an arbitrary file); runs `git mv
   <script_path> <dest_dir>/<basename>` via `subprocess`; on success, calls `generate_scripts_registry.build_registry` + writes it, so the moved file's row shifts from "Scratch" to "Scripts" in the
   same command.
3. `main()` — `argparse` with two mutually exclusive modes: `--list [--days N]` (default `N` matches the convergence-rule spirit — pick a sensible default such as 30 and state the reasoning in the
   docstring, e.g. "long enough that a script surviving this long has proven reusable, short enough that a monthly promotion pass catches it") prints candidates as `<date>\t<path>\t<purpose>`;
   `--script <path>` promotes exactly that one file. No default no-argument behaviour that moves anything — the whole point is this is never auto-triggered.

**Tests:** written in SSR-4, not here.

**Commit:** `feat(scratch-registry): add promote_scratch_scripts.py`

## SSR-3 — `scratch/SCRATCH.md`: registry + sub-agent duplicate-check section

**Files to change / create:**
- `scratch/SCRATCH.md` — add one new section (placement: directly after "## Naming", before "## The convergence rule" — the duplicate-check is a pre-write gate, the convergence rule is a post-write
  graduation rule, so ordering should match the actual workflow sequence)

**What to implement:**

1. New section, e.g. `## Registry & duplicate-check (before writing a new scratch script)`, stating as a hard requirement: before creating any new scratch analysis/probe script, delegate to a
   sub-agent (the `task` or `general-purpose` agent type) with a bounded objective — read root `SCRIPTS.md` (both the "Scripts" and "Scratch" sections) and search for existing coverage of the
   topic/question at hand; if a match is found, report its path and stop (reuse it, do not write a new one); if no match is found, have that same sub-agent create the new
   `scratch/<YYYY-MM-DD>_<topic>_<purpose>.py` stub per the naming convention above, then return control.
2. State explicitly why this is delegated rather than done inline: keeps the duplicate-check + boilerplate-stub-creation cost off the main session's context, and makes the check a named, auditable
   step instead of something easy to silently skip under time pressure.
3. Document the two commands this section depends on: `python scripts/dev/generate_scripts_registry.py` (regenerate the registry — also run automatically by `session-close`, see SSR-6) and `python
   scripts/dev/promote_scratch_scripts.py --list [--days N]` / `--script <path>` (manual promotion — run at the operator's discretion, no automatic weekly/monthly trigger exists).
4. Do not restate the convergence rule already below this new section — this section is only about the pre-write duplicate check and the registry/promotion commands, not about when a script graduates.

**Tests:** none — docs-only change.

**Commit:** `docs(scratch-registry): add duplicate-check and registry section to SCRATCH.md`
